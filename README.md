# 渋滞と財政 — city MVP

シティーズスカイライン的なものの、**面白さの根だけを取り出した最小の検証台**。
3D も交通アニメーションも建物のモデルも無い。あるのは
**渋滞が勝手に発生すること**と、**それが財政に返ってくること**の2つだけ。

作った目的は遊ぶことではなく、**「渋滞対策と財務管理は本当に面白いのか」を
1年かける前に確かめること**にある。

## 動かす

ビルド不要。ES modules をそのまま読むので、静的サーバに置けば動く。

```sh
python3 -m http.server 8000     # file:// では動かない（CORS）
open http://localhost:8000/
```

単一ファイル版が要るときだけ：

```sh
node tools/build.mjs            # → dist/index.html （AirDrop でも動く）
```

## GitHub Pages に置く

**public リポジトリにすること。** GitHub Free では Pages は public のみで、
private から公開するには Pro 以上が要る。仮に Pro でもサイト自体は公開される。

1. このディレクトリだけを別の public リポジトリに置く
2. Settings → Pages → Source: `Deploy from a branch` → `main` / `/ (root)`
3. `https://<user>.github.io/<repo>/` で開ける

iPad の Safari で開いて「ホーム画面に追加」すると全画面のアプリになる
（`manifest.webmanifest` を置いてある）。App Store も Xcode も要らない。

## 仕組み

### 交通：利用者均衡配分

車を1台ずつ経路探索させる方式（Cities: Skylines がやっていること）は取らない。
CPU を食い尽くすうえ、**渋滞の理由が説明できない**からだ。

代わりに交通計画の教科書どおり、重力モデルで行き先を決め、
BPR 関数（混むほど遅くなる）のもとで利用者均衡を MSA で解く。こうすると

- 渋滞は**勝手に**現れる。どこが詰まるかを作り込む必要がない
- 「どの住宅の、通勤か買物かが、この道を何%埋めているか」を数字で言える

後者が効く。詰まりの理由が読めなければ、対策はただの博打になる。

**BPR の α は 0.15 ではなく 0.60 にしてある。** 0.15 は実務の較正値で、
v/c 0.9 でも旅行時間が1割しか伸びない。ゲームには優しすぎて痛みが伝わらない。

### 財政：予算が遅れて渋滞になる

```
道路予算 → 舗装状態 → 道路容量 → 渋滞 → 通勤時間 → 人口と税収 → 道路予算
```

舗装状態は予算に**徐々に**近づくので、削減の報いは数ヶ月遅れて来る。
「今月の帳尻を合わせた代償を半年後に払う」。これが管理を遊びにする。

行政費が人口に比例するので、**成長は自動では黒字化しない**。

### 速さのために踏んだ手

満杯のマップ（道路174・建物162・人口22,000）で 175ms/月 → **64ms/月**。
通常規模なら 2ms/月。結果は一切変えていない。

1. **ウォームスタート** — 道路網が変わらなければ前月の交通量から解き直す（反復 14→6）
2. **逆順カスケード載荷** — OD毎の経路遡上 O(原点×目的地×経路長) を O(ノード) に
3. **CSR 隣接表と型付きヒープ** — 配列の配列をやめて GC を減らす

## 検証

```sh
node test/sim.mjs         # 標準の町を60ヶ月
node test/scenarios.mjs   # 操作が結果に返るかの検証
```

`scenarios.mjs` で確かめていること：

| 検証 | 結果 |
|---|---|
| 道路予算を40%に削る | 収支 +523→+804 に改善するが、舗装41%・渋滞0.63・人口−200 で **収支は+690に劣化** |
| 工場2つを住宅の近くへ移す | 通勤 10.6→8.5分、人口 **+23%**、収支 **+88%** |
| バイパスを1本足す | 人口ほぼ変わらず、維持費で **収支 531→430 に悪化** |

3つ目が特に大事で、**道路投資は回収できないことがある**。
足せば良くなるとは限らない、が成立している。

## 分かっていて割り切ったこと

- **道路はグリッド、直線とL字のみ。** 曲線道路は当たり判定・接続判定・
  建物配置の全部を複雑にする。工数が桁で変わるので取らない
- **車は個体として存在しない。** 画面を車が走る絵は出ない
- **診断は発生源までで、行き先の内訳は出さない。** カスケード載荷にした代償。
  必要になったら選択したリンクだけ別計算すればよい
- 建物は1タイル1種類。区画も密度も無い
